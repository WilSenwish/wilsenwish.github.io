## 项目经历

### 项目 1｜自研 APM 可观测性平台 ｜2019.06 - 至今
**独立全栈开发（Agent / 服务端 / 管理端 / UI）**

**技术栈**：Java、SPI、RocketMQ（ACL 改造）、Protostuff、MongoDB、TransmittableThreadLocal、Actuator、Vue

**项目描述**：业务系统从集中式向分布式演进后，跨服务链路缺乏统一可观测能力。因**多机房网络隔离、老系统需零侵入接入、共享中间件需权限隔离**等约束，调研 SkyWalking / Prometheus / OpenTelemetry 后选择自研轻量 APM；数据模型对标主流可观测体系，覆盖 **Trace、Metric、Log/Event、JVM、线程池、异常告警**。

**核心工作**

1. **选型与架构**：对比 SkyWalking / Prometheus / OpenTelemetry 的接入成本与网络约束后，采用微内核 + SPI 插件架构；Agent SDK 支持零代码接入与显式埋点双模式，控制业务侵入与运行开销。
2. **分布式 Trace**：基于 TransmittableThreadLocal 透传上下文，解决跨服务层级嵌套与时间序对齐；多级采样责任链按接口 / Debug / 预热 / 异常 / 慢事件 / 兜底比例采样，平衡采集完整性与性能损耗。
3. **上报通道**：推拉双模——RocketMQ 主动上报 + 中心端 HTTP / Actuator 端点按需拉取，适配不开放外网的客户内网环境；Protostuff 序列化降带宽；完成 **RocketMQ ACL 改造**，实现 Group / Topic 级权限隔离。
4. **自身稳定性**：采集与上报复用自研可监控线程池（队列水位 / 活跃线程 / 任务耗时可观测），监控链路不拖慢业务；异常与慢日志邮件预警 + **12 类告警**。
5. **存储与展示**：链路与指标数据落 MongoDB，管理端与 UI 基于 Vue。

**结果**：接入 **17 个业务系统 / 24 个服务 / 47 台机器**（8 个学生综评客户部署实例内 evaluate / exam 合并计 1 个系统，另含 4 个微服务、小学 / 职教 / AI 实验班 / 校友系统；47 为去重机器数），迭代 30+ 次；分钟级统计 **P99 < 1s**，异常发现到告警推送 **< 3min**，故障定位由「逐台排查」变为「按链路定位」。

**项目描述**：面向教育主管部门与学校的综合素质评价平台，**按客户独立部署**（一套代码基线交付多个客户，客户间数据物理隔离）；以中学学生综评为基底拓展 5 套业务系统。在用 **8 个客户部署实例**（含清华附中（初）、央视综合等学校 / 机构级客户），覆盖 7,200+ 所学校、1,350 万+ 师生；累计评价记录 **13.6 亿+ 条**，单实例最大 **5.47 亿条**。

**核心工作**

1. **服务端架构（从 0 到 1）**：负责架构设计、库表结构设计与核心模块实现；按客户独立部署实现数据隔离。
2. **存储与缓存**：MySQL 承载主业务数据，MongoDB 承载记录类与统计数据，Redis + Caffeine 两级缓存承接高频读，并持续优化列表类接口的响应耗时。
3. **性能治理**：从慢日志与执行计划入手，补齐缺失索引，给无条件全量查询加上必填条件与分页，再把统计规则落成预聚合结果表——统计类慢接口**十秒级 → 毫秒级**；集中填报线上持续峰值 **TPS 3,000 / TPM 18 万**。
4. **异步化与隔离**：自研可监控线程池将导入导出、报告册生成移出同步链路；**80 万条数据单机报告册生成 10h → 5h**，支持多机并行分片。
5. **权限与安全**：接口操作权限切面校验 + 接口内数据权限校验（规则化模板与脚本批量生成 / 校验）；隐私数据加密改造覆盖 **890 万+ 条记录**；基于 Redis 滑动窗口实现接口级限流。
6. **能力沉淀**：基于 QLExpress 的统计规则引擎（配置化 + 热更新），应用于小学版 / 职业版 / 教师系统；完成 Word → PDF 报告册方案（poi-tl + JODConverter）的选型与落地，推广至人工智能实验班与信息采集系统。

**一次跑批故障复盘**：考试成绩统计跑批在数据量上涨后出现卡死，甚至撑爆堆内存。最突出的慢 SQL 是「1 条缺索引 + 2 条无条件全量查询」，小数据量时无感，量一上来直接放大。排查按慢日志 → EXPLAIN 执行计划 → APM 链路定位耗时节点 → `jmap` dump + MAT 分析堆占用（Dominator Tree / Retained Heap / Path to GC Roots）推进；修复上补组合索引、强制必填条件 + 时间窗分页、统计落预聚合结果表，并把耗时任务改为分批流式处理、移出同步链路异步隔离。跑批随后恢复稳定，堆占用回落。

**结果**：支撑 **8 个客户部署实例**集中填报，峰值时段核心接口未触发超时告警；13.6 亿+ 条记录在线稳定。
