## 项目经历

### 项目 1｜自研 APM 可观测性平台｜2019.06 - 至今
**独立全栈开发（Agent / 服务端 / 管理端 / UI）**

**技术栈**：Java、SPI、Spring Boot、RocketMQ（ACL 改造）、Protostuff、MongoDB、Redis、TransmittableThreadLocal、Actuator、Vue

**项目描述**：业务系统从集中式向分布式演进后，跨服务链路缺乏统一可观测能力。因**机房网络多样性**约束，调研 SkyWalking / Prometheus / OpenTelemetry 后选择自研轻量 APM；数据模型对标主流可观测体系，采集 **Trace、日志 / 事件、接口性能、JVM / OS、线程池、异常与业务事件**。口径说明：8 个学生综评客户部署实例内，学生综评与考试系统合并计 1 个系统；机器数为去重统计。

**核心工作**

1. **选型与架构**：对比 SkyWalking / Prometheus / OpenTelemetry 的接入成本与网络约束后，采用微内核 + SPI 插件架构；Agent SDK 支持零代码接入与显式埋点双模式，控制业务侵入与运行开销。
2. **分布式 Trace**：基于 TransmittableThreadLocal 透传上下文，解决跨服务层级嵌套与时间序对齐；多级采样责任链按接口 / Debug / 预热 / 异常 / 慢事件 / 兜底比例采样，平衡采集完整性与性能损耗。
3. **上报通道**：推拉双模——RocketMQ 主动上报 + 中心端 HTTP / Actuator 端点按需拉取，适配不开放外网的客户内网环境；Protostuff 序列化降带宽；完成 **RocketMQ ACL 改造**，用于集群整体安全防护。
4. **自身稳定性**：采集与上报复用自研可监控线程池（队列水位 / 活跃线程 / 任务耗时可观测），监控链路不拖慢业务；异常与慢日志邮件预警 + **12 类告警**。
5. **存储与展示**：链路与指标数据落 MongoDB，管理端与 UI 基于 Vue。
6. **AI 链路可观测性预研**：在 AI 辅助异常归因预研中，关注 LLM 调用链的可观测性维度（Function Calling 耗时、检索命中率、token 消耗），将已有的 Trace 采集能力向 AI 链路延伸。

**结果**：覆盖 **17 个业务系统 / 24 个服务 / 47 台机器**（含 4 个微服务、小学 / 职教 / AI 实验班 / 校友系统），迭代 30+ 次；异常发现到告警推送 **< 3min**，故障定位由「逐台排查」变为「按链路定位」。
